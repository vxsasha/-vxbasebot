# Бот-база скамеров

```
main.py          запуск
app.py, config.py, db.py, texts.py, handlers.py   код бота
*.jpg            баннеры карточек (можно положить в папку assets/)
requirements.txt зависимости
railway.json     команда запуска для Railway
```

## Запуск на Railway

1. **GitHub.** Загрузите все файлы в приватный репозиторий (Add file → Upload files).
2. **Railway.** New Project → Deploy from GitHub repo.
   Если репозитория нет в списке: Configure GitHub App → Repository access → выберите репозиторий → Save.
3. **Variables** (вкладка сервиса):
   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | токен бота от @BotFather |
   | `OWNER_ID` | ваш Telegram ID (несколько - через запятую) |
4. **Volume - обязательно**, иначе база удаляется при каждом деплое:
   правой кнопкой по сервису (или Ctrl+K) → **Add Volume** → Mount path: `/data`.
   Бот сам найдёт Volume и будет хранить базу там.
5. **Проверка.** Deployments → View logs: должна появиться строка `Бот @... запущен`
   и `База: /data/base.db`. Если в логах предупреждение про Volume - вернитесь к шагу 4.

Боту в чате дайте права администратора - тогда он видит все сообщения, `чек` работает,
и бот запоминает людей для поиска по @юзу.

Один токен - один запущенный бот: если этот токен запущен где-то ещё, Telegram выдаст ошибку `Conflict`.

## Команды

**Для всех**
- `/start` - меню с кнопками
- `/me` - проверить себя
- `/check @юз` или `/check ID` - проверка в базе (можно ответом на сообщение)
- `чек @юз` / `чек ID` - то же без слеша
- `/garants` - список гарантов
- `/admins` - список администраторов
- `/info` - информация о базе
- `/help` - команды, доступные вам

**Владелец и администраторы**
- `/add @юз/ID причина ссылка_на_пруф` - занести скамера
- `/add_r @юз/ID причина ссылка_на_пруф` - занести подозрительного
- `/add ID @юз причина ссылка_на_пруф` - сразу по ID и юзу (тогда `чек @юз` тоже найдёт)

Повторный `/add` или `/add_r` добавляет ещё одну запись «причина + пруф», в карточке видны все.
Если бот ещё не знает ID юза, человек заносится по юзу («Айди: неизвестен»);
как только он напишет боту или в чат с ботом, запись сама перейдёт на его ID.
Если человек занесён по ID без юза, бот при проверке или /add сам спрашивает у Telegram его юз и имя
(получается для тех, кого бот уже видел) и объединяет записи.

**Только владелец**
- `/hire_admin ID` - сделать администратором (сразу попадает в список админов)
- `/hire_garant ID [ссылка на канал]` - сделать гарантом (сразу попадает в список гарантов)
- `/channel ID ссылка` - канал гаранта в карточке проверки и в /garants (без ссылки - убрать)
- `/role_norm ID` - снять любую роль и все записи, человек становится обычным пользователем
- `/addadmin ID` / `/deladmin ID` - добавить / убрать из списка админов
- `/addgarant ID` / `/delgarant ID` - добавить / убрать из списка гарантов

Вместо ID можно писать `@юз`, если человек уже писал боту или в чат с ботом:
Telegram не даёт ботам узнать ID по юзу.

## Необязательные переменные

- `REPORT_URL` - куда ведёт «предложка» (по умолчанию `https://t.me/vxbaseroblox`)
- `DB_PATH` - свой путь к файлу базы (обычно не нужен: бот сам использует Volume)

## Запуск на своём ПК

Python 3.11+, затем:
```
pip install -r requirements.txt
```
Скопируйте `.env.example` в `.env`, впишите `BOT_TOKEN` и `OWNER_ID` и запустите `python main.py`.
